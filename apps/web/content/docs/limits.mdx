---
title: Limits
description: What the SDK does not promise, and the provider and browser limits that apply.
icon: Ruler
---

The SDK sets no arbitrary limit. These apply:

| Limit | Value |
|---|---|
| Parts per upload | 10,000 (S3, R2) — parts grow above 8 MiB for files over ~78 GiB |
| Part size | 5 MiB minimum (except the last), 5 GiB maximum |
| Object size | 50 TiB (AWS), ~5 TiB (R2) |
| Presigned URL lifetime | 7 days (SigV4); less with temporary credentials |
| Incomplete upload retention | R2 7 days, MinIO 24 h by default, AWS until your lifecycle rule |

Browser realities:

- **iOS** freezes background tabs: uploads pause when the user switches apps and continue when they come back. There is
  no background upload API on iOS Safari.
- **Safari** may delete IndexedDB after 7 days without a visit; store the ticket server-side (`onUploadStarted`) when
  that matters.
- Re-selecting from the **iOS Photos picker** can deliver a re-encoded file; it is detected and refused, never mixed.
- Hashing reads the file on the main thread in 1 MiB slices (about 1 GB/s on a laptop, slower on phones).
